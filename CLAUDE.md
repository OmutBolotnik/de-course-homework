# CLAUDE.md

Правила роботи в цьому репозиторії (домашки курсу Data Engineering). Зібрано з того, що
користувач просив запам'ятати.

## Середовище

- **Arch Linux у WSL2 на Windows**, термінал інтегрований у VSCode.
- Пакети — лише через `pacman` (напр. `sudo pacman -S jdk17-openjdk`), ніколи `apt` / `apt-get`.
- WSL2: `PATH` містить довгий список `/mnt/c/...` — враховувати при діагностиці «command not found»
  (напр. відсутній `java`).

## Команди й правки

- **Не запускати команди самостійно.** На прохання «дай команду для X» — показати команду в блоці
  коду й зупинитись. Виконувати лише на однозначну вказівку: «запусти», «виконай», «run it».
  Згода з планом — це не дозвіл виконувати.
- **Питати перед будь-якою правкою файлу.** Перед кожним Edit/Write — описати зміну й дочекатись
  «так», навіть для однорядкової, однозначної, явно запитаної зміни. Винятків «бо це дрібниця» нема.
- **Не перевіряти власні правки.** Після успішного Edit/Write не запускати `cat` / `grep` /
  `git check-ignore` тощо, щоб «переконатись, що зберіглось». Перевіряти лише те, що правка сама
  гарантувати не може (збірка, тести, поведінка під час виконання).

## Стиль коду

- **SQL: ключові слова ВЕЛИКИМИ** — `SELECT`, `FROM`, `WHERE`, `JOIN`, `ON`, `AS`, `GROUP BY`,
  `ORDER BY`, `CASE WHEN`, `PARTITION BY`, `OVER`… Імена таблиць / колонок і функції — як є.
  Стосується всього SQL: dbt-моделей, ad-hoc запитів, прикладів у поясненнях.

## Домашки: скоп і авторство

- **Правити лише те, що позначено для студента** («ви» / TODO-заглушки). «ДАНО»-код (`main()`,
  дані скрипти, схема БД, макроси) не чіпати й не пропонувати змін у ньому — навіть якщо для
  проду так було б краще.
- У рев'ю розділяти **[у скопі]** (зміна всередині TODO-функцій / файлів студента) і
  **[поза скопом]**; поза-скопне — матеріал для нотаток, не для коду.
- **`NOTES.md` пише лише користувач.** Не писати туди й не пропонувати переносити туди свої
  висновки. Зауваження асистента — у `CLAUDE_NOTES.md`, план — у `CLAUDE_PLAN.md`, випадки для
  журналу ШІ — у `CLAUDE_EXAMPLES.md` (поруч із `NOTES.md`).

## Поради «як у проді»

- **Звіряти пораду з кодом, перш ніж її давати.** Не підставляти загальні best practices
  («додай логування», «зроби одним проходом», «додай параметр») без перевірки проти:
  - наявних точок кешування / матеріалізації (чи не дублює порада вже кешоване сканування);
  - фіксованих сигнатур і контрактів, на які спирається оркестрація;
  - конвенцій файлу (лінивість, чистота функцій);
  - реального DDL / конфігів (а не припущення «індексу, мабуть, нема»).
- Цю перевірку робити до відповіді, а не чекати, поки користувач витягне її уточненнями.
